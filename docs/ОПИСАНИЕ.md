# Описание программы met21 (Фортран) и её Python-версии

## 1. Что считает программа

Программа моделирует стационарное турбулентное течение и горение метана в
кислороде в осесимметричной камере сгорания. Схема камеры, слева направо:

```
 r
 ^          уступ (торец), щель окислителя O2
 |          v
 |          +---------------------+
 |          |                     \        конус сужения (tgY)
 |  +-------+   камера сгорания     \
 |  | пред- |       (Dks, Lks)        \______
 |  | камера|                          | выход   критическое сечение Dkr
 |  |(Dprk, |                          |
 |  | Lprk) |                          |
 +--+-------+--------------------------+----> x (ось симметрии)
    ^ головка: на оси центральная струя O2 (Dcmw), кольцевая щель CH4 (DOGOR, DELGOR)
```

* Через головку в предкамеру подаются горючее CH4 (кольцевая щель) и часть
  окислителя O2 (центральная струя).
* Основная часть окислителя подаётся через кольцевую щель на торце уступа.
* Продукты сгорания уходят через сужающееся сопло.

Для нескольких значений коэффициента избытка окислителя α программа
считает поле течения: функцию тока ψ, вихрь ω, закрутку, турбулентную
вязкость. Кроме того, она считает поля концентраций CH4, O2, CO2, H2O,
H2, CO, OH, энтальпии, температуры и плотности. Для каждого α выводится
**коэффициент полноты сгорания Fkomp**.

### Математическая модель

* **Уравнения движения** записаны в переменных «вихрь ω — функция тока ψ»
  (уравнения Госмена–Сполдинга для осесимметричного течения
  переменной плотности). Скорости находятся из ψ:
  V1 = ∂ψ/∂r / (ρ r), V2 = −∂ψ/∂x / (ρ r).
* **Закрутка** r·W решается отдельным уравнением переноса.
* **Турбулентная вязкость** задаётся алгебраической моделью: μт
  пропорциональна ρ^0.666, характерному размеру и кинетической энергии
  входящих струй в степени 1/3. Энергия струй своя для предкамеры и для
  камеры.
* **Перенос компонентов и энтальпии** описывается уравнениями
  конвекции–диффузии с одинаковым коэффициентом обмена (числа Шмидта и
  Прандтля равны 1). Источников в уравнениях переноса нет.
* **Химия**: модель «смешалось — сгорело» с бесконечно быстрой реакцией.
  Если в узле T ≥ ROM1, весь недостающий компонент мгновенно реагирует.
  Продукты образуются по брутто-схемам с фиксированными долями CO2, CO,
  H2O, H2, OH. Отдельно разобраны случаи избытка горючего (O2/CH4 ≤ 3.9166)
  и избытка окислителя. Затем массовые доли нормируются на 1.
* **Температура** получается из энтальпии и состава: T = (H + Σ теплот
  образования) / Σ(cp·Y) + 293 с эмпирическими поправками 1.1 и 1.2 в
  зависимости от локального α. Ограничения: 293 ≤ T ≤ 4500 K.
* **Плотность** считается по уравнению состояния идеальной смеси
  ρ = p / (R·T·ΣYi/Mi) с релаксацией 0.1. Давление p(x) берётся из
  одномерного газодинамического расчёта сопла. В цилиндрической части
  давление падает линейно, в сужении определяется по функции расхода
  q(λ) методом деления отрезка пополам.
* **Расходы** определяются через критическое сечение: Ms = P·Fкр/β(α),
  где β(α) задан полиномиальной аппроксимацией. Расходы разделяются на
  горючее и окислитель по KM = 4α. Часть окислителя уходит в центральную
  струю пропорционально площадям отверстий.

### Численный метод

* Неравномерная разностная сетка IN × JN (46 × 22). Узлы привязаны к
  границам: оси, краям щелей, стенкам, уступу и критическому сечению.
* Схема против потока для конвекции (метод Госмена), центральные разности
  для диффузии.
* Итерации Гаусса–Зейделя с нижней релаксацией 0.1 для вихря и
  плотности; 1000 итераций на вариант.
* Граничные условия для вихря на стенках вычисляются из функции тока по
  формулам Вудса второго порядка.
* Первые NPRINT = 200 итераций первого варианта — «разгон»: вихрь не
  решается, течение считается потенциальным.
* На 18-й итерации в зоне предкамеры химия включается принудительно,
  это поджиг.
* Аварийная остановка варианта: если на итерации ≥ 85 скорость где-то
  превышает 27000 м/с, к счётчику прибавляется 1000. В протоколе это
  видно как NITER > NMAX.

## 2. Программа на Фортране (папка `fortran_original/`)

Семь файлов, общие данные передаются через COMMON-блоки. Главный массив
`A(46,22,17)` хранит все 17 переменных в каждом узле сетки.

| № в A | Переменная | | № в A | Переменная |
|---|---|---|---|---|
| 1 NW | вихрь ω | | 10 NMU1 | энтальпия |
| 2 NF | функция тока ψ | | 11 NMU | турбулентная вязкость |
| 3 NMFU1 | CH4 | | 12 NRO3 | плотность |
| 4 NMOX1 | O2 | | 13 NT | температура |
| 5 NMPR1 | CO2 | | 14 NV1 | осевая скорость |
| 6 NMPR2 | H2O | | 15 NV2 | радиальная скорость |
| 7 NMDF | H2 | | 16 NMU2 | закрутка r·W |
| 8 NMOX2 | CO | | 17 NK | не используется |
| 9 NMFU2 | OH | | | |

### RK1.FOR
* **BLOCK DATA** — все исходные данные: геометрия в мм, давление,
  энтальпия, номера узлов сетки, число итераций, начальные таблицы.
* **INIT** — граничные и начальные условия:
  * диапазоны расчётной области по каждой строке сетки (IMIN, IMAX);
  * профили на входах: скорость, состав, плотность, температура 298 K,
    энтальпия, функция тока;
  * начальное поле: предкамера заполнена горючим, камера — окислителем,
    вдоль оси «запал» с T = ROM1 + 10.

### RK2.FOR — главная программа
Цикл по вариантам. Для каждого варианта:
1. α увеличивается на 0.2.
2. Строится сетка (GRID).
3. Рассчитывается давление по длине (газодинамика сопла).
4. Вычисляются β(α), расходы Ms, Mok, Mgor, плотности и скорости на
   входах. Геометрия переводится в метры и записывается обратно (её
   использует следующий вариант).
5. Вызывается INIT, затем в файл `shi10.dat` печатаются исходные данные и
   расходы.
6. Выполняются 1000 итераций, каждая состоит из VISCOS → VELDIS → CONVEC
   → EQN.
7. По составу в выходном сечении считается **коэффициент полноты
   сгорания** Fkomp. При α ≤ 1 он считается по окислителю, при α > 1 — по
   горючему. Результат печатается.
8. Считаются, но не печатаются комплекс FIbeta и расходы через входы
   FIOP, FIOS.
9. PRINT1 записывает поля ω, ψ, CH4, O2 в `shi20.dat`.

В файле есть «мёртвый» код. Таблица α/β на метках 91–99 никогда не
выполняется: её обходит `GO TO 145`.

### RK3.FOR — EQN
Один шаг Гаусса–Зейделя по всем уравнениям:
1. Вихрь ω (кроме разгонных итераций). Для угловых точек у входов
   действует особая формула.
2. Функция тока ψ.
3. Закрутка r·W.
4. Энтальпия и компоненты 10…3 (уравнения переноса).
5. Нормировка массовых долей.
6. **Химическая реакция** в каждом узле с T ≥ ROM1 (или при поджиге на
   18-й итерации), затем снова нормировка.
7. Вызов BOUND.

### RK4.FOR — VISCOS
1. Отрицательные концентрации обнуляются, доли нормируются.
2. **Температура** по энтальпии и составу.
3. **Плотность** по уравнению состояния.
4. **Турбулентная вязкость** μт.

В этом же файле считается «равновесная» температура YYY, но она
использовалась только в закомментированной печати.

### RK5.FOR
* **VELDIS** — скорости V1, V2 из ψ, кинетическая энергия, источник в
  уравнении вихря (бароклинный член и вклад закрутки). Здесь же проверка
  на расходимость (V > 27000 м/с).
* **CONVEC** — коэффициенты разностной схемы: конвективные (против
  потока) и диффузионные.
* **GRID** — построение сетки по геометрии:
  * радиальные узлы равномерно между границами щелей и стенок;
  * осевые узлы в предкамере и в цилиндре;
  * на конусе по одному осевому узлу на каждый радиальный, с наклоном tgY;
  * выходной участок длиной 1 мм.

  Узел критического сечения JC подбирается по Dkr. В первом варианте все
  размеры переводятся из мм в м.

### RK6.FOR — SORCE
Источниковые члены: для ω это член из VELDIS, для ψ — сам вихрь, для
остальных уравнений 0.

### RK7.FOR
* **BOUND** — граничные условия на каждой итерации:
  * на стенках нулевой поток вещества (значения копируются из соседнего
    узла);
  * вихрь на стенках по формулам Вудса;
  * условие симметрии на оси;
  * «мягкое» условие на выходе.
* **PRINT1** — вывод полей в `shi20.dat`.
* **PRINT** — табличная печать, её вызов закомментирован.

### Выходные файлы
* `shi10.dat` — протокол. По каждому варианту: P, α, KM, β, расходы,
  скорости, плотности, номера узлов сетки, геометрия, число итераций и
  Fkomp.
* `shi20.dat` — поля. Для каждого варианта, для всех 46 × 22 узлов:
  ω, ψ, CH4, O2, X1, X2 (по ним строились картины изолиний в Surfer,
  отсюда файл SHI20.GRD).

### Особенности и найденные проблемы
* Расчёт ведётся в одинарной точности (REAL*4). Из-за ошибки округления в
  GRID у вариантов 2–5 критическое сечение сдвигается на один узел, и
  расчёт расходится (NITER = 2203, Fkomp = 0). В двойной точности
  считаются все варианты.
* Параметр ALKD (длина до критики) на результат не влияет: GRID
  перезаписывает её через tgY.
* Шаг по α (0.2) зашит в код.

## 3. Python-версия (папка `metan/`)

| Модуль | Что делает |
|---|---|
| `params.py` | Класс `Params` — все исходные данные с подписями, единицами, группами и подробными описаниями (`HELP`). Проверка корректности (`validate`), сохранение и загрузка JSON, список вариантов α. |
| `kernels.py` | Вычислительное ядро: построчный перевод VISCOS, VELDIS, CONVEC, EQN (+SORCE), BOUND. Индексация с 1, порядок обхода и все ветвления как в Фортране. Компилируется numba в машинный код. |
| `solver.py` | Класс `Solver`: главная программа RK2 (цикл вариантов, газодинамика сопла, расходы, Fkomp, FIbeta), GRID, INIT, PRINT1. Точность float64 или float32. Возвращает `Results` (список `VariantResult` с полями и всеми величинами) и пишет `shi10.dat` и `shi20.dat` в формате Фортрана. Поддерживает индикатор прогресса и остановку. |
| `fortran_format.py` | Форматирование чисел как в FORMAT Фортрана (E11.4, F6.2, I4…), чтобы файлы совпадали символ в символ. |
| `plotting.py` | Построение полей: точный контур камеры по сетке, заливка без дыр у стенок, штриховка стенок, отметка входных щелей, линии тока, режим «как в методичке»; схема камеры с размерами и сеткой; графики сходимости, серий, разности; оформление под светлую/тёмную тему. |
| `analysis.py` | Профили по радиусу и вдоль оси, среднемассовые T и состав в сечении (вес - расход между узлами, разность ψ), перенос поля на общую сетку и разность двух расчётов. |
| `studies.py` | Серии по любому параметру (параллельно в несколько потоков), подбор параметров на максимум Fkomp (поиск по образцу с уменьшением шага), построение сетки ×2/×3 той же камеры и сравнение результатов. |
| `report.py` | Отчёт Word (.docx): исходные данные, схема, таблицы, рисунки с подписями, серия, подбор, проверка сетки. |
| `app/` | Новая десктопная программа (CustomTkinter, оформление «Инженерный пульт», светлая/тёмная тема): `main.py` - окно, фоновые задачи; `sidebar.py` - исходные данные, справка, мини-схема; `pages.py`, `pages2.py` - вкладки. |
| `gui_classic.py` | Прежняя десктопная программа (tkinter), сохранена без изменений функционала. |
| `cli.py`, `__main__.py` | Командная строка: `python -m metan …`. |

### Новая десктопная программа (Metan)
Вкладки: Поля, Профили, Сходимость, Анимация, Геометрия, Серии, Подбор,
Сравнение, Сетка ×2, Файлы .dat; кнопка «Отчёт Word»; плашки вариантов α с
Fkomp; справа - ключевые результаты, мини-график Fkomp(α) и папка с файлами
shi10.dat / shi20.dat. Что делает каждая вкладка - в README.

Решатель для неё дополнительно (не меняя результатов) записывает историю
сходимости - максимальное относительное изменение ω, ψ, T, CH4 за каждую
итерацию - и, если задано, кадры полей для анимации. Зона принудительного
поджига на 18-й итерации задана как узлы I = 3 … IC2+1 (в оригинале 3 … 11,
что при IC2 = 10 то же самое), чтобы на более мелкой сетке она оставалась
той же областью предкамеры.

Наблюдения при проверке: при Dkr = 10 мм (остальное по умолчанию) расчёт
расходится во всех вариантах; на сетке ×2 вариант α = 1.0 может расходиться -
схема Гаусса-Зейделя с релаксацией из оригинала на мелкой сетке менее
устойчива.

### Прежняя десктопная программа (Metan-Classic)
* **Параметры.** Все исходные данные на вкладках «Режим», «Геометрия»,
  «Сетка», «Расчёт и вывод». При наведении на параметр показывается
  подробное описание (всплывающая подсказка и панель «Справка по
  параметру»). Наборы параметров можно открыть и сохранить в JSON, есть
  сброс к значениям по умолчанию. Перед запуском видно, при каких α будут
  считаться варианты.
* **Расчёт.** Идёт в фоне: окно не зависает, есть полоса прогресса и
  кнопка «Стоп». Результаты автоматически записываются в `shi10.dat` и
  `shi20.dat`.
* **Сводка.** Таблица по вариантам: α, KM, β, расходы, скорости, NITER,
  Fkomp, FIbeta, статус. Варианты с расходимостью выделены.
* **Поля.** Любая из 16 величин; заливка, изолинии или оба вида сразу;
  зеркальное отображение, линии тока, подписи изолиний, оси в мм или м;
  кнопка «Как в методичке». Рисунок можно сохранить в PNG, PDF или SVG,
  поля можно выгрузить в CSV.
* **Протокол.** Показывает содержимое `shi10.dat`.

### Командная строка
`python -m metan [-p params.json] [-o папка] [--set ИМЯ=ЗНАЧЕНИЕ] [--precision float32|float64] [--dump-params файл]`

### Проверка правильности (`tests/`)
* В режиме float64 Python-версия даёт файлы `shi10.dat` и `shi20.dat`,
  **побайтно совпадающие** с Фортраном, собранным gfortran в двойной
  точности (все 5 вариантов).
* В режиме float32 `shi10.dat` совпадает с исходной программой (REAL*4)
  побайтно, включая расходимость вариантов 2–5.
* Проверяются также форматирование, параметры и разбор JSON.

### Сборка
* `install.bat`, `run_gui.bat`, `run_cli.bat` — запуск через Python.
* `build_exe.bat` и GitHub Actions — сборка `Metan.exe` (PyInstaller) с
  автоматической проверкой. numpy ограничен версией < 2.4, чтобы
  программа работала на процессорах без SSE4.2 (например, AMD Phenom II).
